# Offline supported content

P3-A implements explicit `quizpack-content.v1` / `quizpack-content.v2` dispatch, strict v2 presentation fields and content-internal reference validation. `index.ts` exports `parseSupportedContent`, `validateSupportedContentReferences` and `getContentJsonSchema` (full schema version strings only). The schema barrel does not import the scoring implementation. New short text counts Unicode code points, preserves source text, rejects lone surrogates and uses equivalent JSON Schema scalar/length constraints.

The shared reference graph was extracted from the legacy P1 implementation. Its optional manifest branch retains the original file/declaration checks; the existing v1 entry is a wrapper with the original state contracts. The new content-only entry does not supply a manifest. It cannot certify ZIP/file integrity, media, licensing, renderer availability, private candidate eligibility or publication. Legacy manifest/parser/CLI/build entry points still reject v2.

`scoring-adapter.ts` separately exports `prepareContentForScoring` and `scorePreparedContent`. Preparation snapshots bounded ordinary JSON once (P1 canonical content budget 2 MiB), parses the declared version, checks internal references and prepares the actual pure scoring core. A private WeakMap binds its opaque handle to the fixed complete content and exact result/report references. Execution accepts answers, runs the actual core and binds the selected report to the complete canonical content SHA. The complete score response envelope is limited to 64 KiB and deeply frozen. Authored-review envelopes and caller-supplied scores are not complete content inputs.

Witness and coverage wrappers await the actual core interfaces; no stubs or fallback scores are provided. The raw ZIP content budget remains 1 MiB. Tests use synthetic declarations and generated fixture pixels only; the large offline content test does not represent a newly accepted package or media execution.
