# QuizPack 与测评资源版本提案

## 当前状态

QuizPack 是 QuizForge 的版本化内容与资源交换边界，不是可执行插件格式。当前文档描述目标架构；D0/D1 已有的 TypeScript 类型、视觉研究和合成演示都不等于运行时 Schema、导入器或安全验证器。

本轮 F1 只建立 `foundation.v1`：它是首批测评参考资源的**有限运行时契约**，用于验证工作区归属、草稿逻辑、结果资料和资源引用。它不冻结完整 `.quizpack` ZIP 格式，不定义数据库持久化格式，也不提供导入、评分、Key、审核或发布实现。F1 结构通过的结论永远是 `publishable=false`。

## 工作区、版本与资源归属

一个 `Product` 即一个测评工作区。工作区持有草稿版本、已发布版本、资源清单、预览证据、审核记录和访问运营历史；不得创建与 `Product` 重复的 `Project` 实体。

每个草稿版本明确引用：内容/规则版本、视觉配方、报告模板、受控组件版本和资源 manifest。发布版本将这些引用及其内容哈希固定为不可变快照。复制、编辑、重新导入或替换资源必须创建新草稿版本；不能原地修改已发布版本、活跃会话或历史报告。

资源默认属于一个工作区版本。引用共享资源时，必须使用已批准的不可变 `assetPackId + version + contentHash`，并在该版本 manifest 中留下用途和裁切等引用记录；不得从可变 public 路径、主题名称或动态 URL 隐式读取。原始生成物、参考材料和程序组件分开存放。

资源记录中的 `source`、`licenseClaim`、作者填写的审核状态或哈希仅是声明和可追溯信息；它们不能证明授权真实有效。自动检查只能验证存在性、哈希和结构，商业授权与内容适用性必须由后续人工审核决定。

## F1：`foundation.v1` 有限契约

F1 面向一个 synthetic 参考测评，最小包括：

- 内容载荷包含工作区稳定 ID、内容版本和 `foundation.v1`；草稿封装另含 productId/draftId/revision/contentHash。F1 不接收“已发布”状态。
- 有限的题目/选项 ID 与顺序；F1 不规定完整题型、条件表达式或分支语言。
- 三个结果资料 ID、标题、展示文案和受控资源引用；它们是 synthetic 夹具，不是评分输出、历史事实或正式人物名单。
- 版本所属资源 manifest：资源 ID、用途、内容哈希、媒体元数据、来源/许可声明和审核声明；不携带图片字节、远程 URL、HTML、脚本或可执行规则。
- 草稿纯逻辑：只提供 editable 草稿创建/更新、revision 冲突和 hash/证据身份对比，不提供审核、复制或冻结状态转换；不读取数据库、文件系统、网络、时钟或浏览器存储，也不授予发布权威。
- 结构验证 CLI：读取受控 JSON 输入，输出可机器读取的错误列表/证据摘要及固定 `publishable=false`；不解压 ZIP、不写数据库、不调用模型、不下载资源、不计算分数。

F1 验证至少拒绝：未知字段、重复稳定 ID、空或跨工作区资源引用、不匹配的草稿内容哈希、非法状态字段或身份/revision 不一致、超出有限长度/数量的文本和集合、任何可执行或远程加载字段。它可以确认“结构适合下一阶段工具开发”，不能确认题目质量、结果可达性、视觉可用性、素材版权或商业发布资格。

## 目标生产流程（后续阶段）

1. 作者在测评工作区研发题目、确定性规则、结果资料、报告、专属视觉与资源；使用固定输入和拒绝样例验证草稿。
2. 构建器将声明式 JSON 与已审核资源封装为 `.quizpack`，记录版本、文件哈希、兼容范围和离线验证证据。
3. QuizForge 在隔离区重新验证不可信上传：容器限额、路径、真实媒体类型、结构、引用、规则、资源和兼容性。通过只能产生草稿 staging。
4. 平台以模拟答案和真实页面状态预览草稿；人工审阅题意、结论、素材/字体授权、娱乐边界和视觉表现。
5. 审核批准后发布不可变版本。运行器读取固定规则及受控组件，服务端完成确定性评分和锁定报告；AI 从不成为确定性运行的依赖。

## 完整 `.quizpack` 的拟议边界（非 F1）

后续格式可包含 `manifest.json`、题目、规则、结果资料、报告、主题/布局、资产 manifest 和纯 JSON 测试用例。完整 manifest 将固定工作区、内容版本、视觉/报告/组件引用、运行时兼容范围和文件哈希。测试包只能是 JSON 输入及期望结果，禁止 `.js`、`.ts`、Python、任意 HTML、宏、动态 URL 和执行字符串。

完整验证应覆盖：

| 类别          | 后续要求                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| 容器          | 限制压缩/解压大小、文件数、压缩比和校验时间；拒绝路径穿越、链接、重复/冲突路径、嵌套/加密压缩包和 ZIP 外写入 |
| Schema 与引用 | 必需文件/字段/版本、有限长度/数量、稳定 ID、哈希、组件/模板/资源引用和兼容范围均受验证                       |
| 引擎          | 固定输入固定结果；多维度边界、原型距离/平分、剧情有界路径与结果可达见证由已注册引擎验证                      |
| 资源          | 真实媒体解析和像素/解码限额；默认拒绝不可信 SVG、脚本、HTML、可执行文件、外链和未授权资源                    |
| 发布          | 验证证据绑定内容哈希；人工批准、权限、预览和不可变版本均满足后才可发布                                       |

哈希证明完整性，不证明作者身份、授权或内容正确性。自动结构通过不替代恶意包防护、人工审核、数据库事务或消费者访问控制。

## 受控组件、升级与回滚

精品布局只能由主项目审核并发布的组件提供。包引用固定 `registryId`、组件版本和 props Schema，不提供源码、import 路径或 URL。未知组件、版本不兼容、危险 props 或资源缺失均阻断导入/发布；视觉组件只消费只读 DTO 和受控回调，不读 Key、不改分数、不调用模型。

发布版本的逻辑、视觉、报告、资源和组件引用均不可变。重复导入同一 `packId/version/hash` 可以幂等返回同一草稿记录；同一版本不同哈希必须拒绝。回滚只改变新激活的当前发布指针，历史会话和报告继续读取原始版本；旧组件和模板必须保持兼容读取。

## 未实现声明

当前没有 ZIP 解包与安全验证、完整 JSON Schema、构建器、数据库记录、认证/审核后台、评分引擎、组件注册表、Key 或发布能力。F1 即使通过，也不改变这一事实。
