# QuizPack 商品包提案（D0）

这是架构提案，不是已实现格式验证器。`contracts.ts` 是编译期草案，不代替 JSON Schema。D2 固定 v1 Schema；D3 验证器；D4 构建工具；D16 运营导入工作流。D0 不创建假装可导入的商业包。

## 研发、验证、导入与运行

1. Codex 在商品工作区推敲题目、评分、结果原型、文案与专属素材；运行固定输入、边界及异常测试。普通测评选择受支持引擎及可信布局，无需修改平台业务代码。
2. 构建器把声明式 JSON 和已审核资源打包为 `.quizpack` ZIP。manifest 固定包、商品、逻辑、视觉、模板和兼容版本，记录文件哈希。运行离线验证产生可审阅证据。
3. QuizForge 在隔离区重新验证不可信上传，限制读取/解压/图片解析，不信任研发端的“通过”标志。验证通过仅能导入草稿；逐领域写入需要事务或可回滚 staging。
4. 预览覆盖真实页面状态与模拟答案，人工检查题意、结论、视觉、素材授权和娱乐边界。包有效不代表内容合理或商业可发布。
5. 审核批准后发布不可变 ProductVersion；核心运行器读取固定内容/规则，通过受控组件渲染，确定性评分并锁定报告。AI 服务不是 DETERMINISTIC/COMPOSED 的依赖。

## ZIP 内部结构（拟议 v1）

```text
manifest.json
questions.json
scoring.json
profiles.json
reports.json
theme.json
assets/
  asset-manifest.json
  <approved images/fonts/audio>
tests/
  cases.json
```

`manifest.json`：packId/packVersion、productId/productVersion、logicVersion、引擎种类/版本、格式和内容 Schema 版本、运行时兼容范围、视觉版本、报告模式/模板、所需注册组件 ID/版本范围、全文件哈希/尺寸/媒体类型、作者及审核来源。兼容范围必须由安全版本比较器检查，不能动态执行表达式。

`questions.json`：稳定题目/选项 ID、题干、顺序、分支节点映射（如适用）。`scoring.json`：维度、有限权重、原型距离/平分策略或分支图/白名单状态变更。`profiles.json`：原型/结局 ID、解释与固定资源引用。`reports.json`：报告模式、完整非 AI 基线、预设组合文案、受控模板 ID/版本；AI_ENHANCED 只能引用平台批准的增强策略，不能带任意 system prompt。

`theme.json`：主题引用或声明式设计语言配置、商品视觉版本、各状态布局引用与受验证 props、进度/选项/转场/揭晓配方、资源包引用。封面、答题、恢复、结果、详细报告、海报分别可定制；详细报告可与结果使用同一已注册组件。

`assets/asset-manifest.json`：每项路径/哈希/宽高/媒体类型、用途、来源、商用授权证据、裁切焦点、审核状态；可引用平台已批准不可变资源包，离线独立验证需提供引用描述和验证证据。完全自包含包更适合独立研发；引用包必须在目标运行器确认存在。音频仅可选且需要用户触发/静音/版权规范。

`tests/cases.json`：纯 JSON 输入与预期分数/原型/结局/路径；边界与拒绝样例。没有可运行测试脚本，禁止 `.js`、`.ts`、Python 或任意可执行内容。平台验证器提供固定测试执行逻辑。

## 验证门槛

| 类别   | 要求                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------ |
| 容器   | 格式、路径、类型、文件数、大小与压缩比受限；拒绝任意代码                                               |
| Schema | 必需文件、字段、版本、有限值、长度/数量限制；拒绝未知危险字段                                          |
| 引用   | 题/选项/维度/原型/结局/模板/素材/布局 ID 唯一且有效，文件哈希一致                                      |
| 引擎   | 固定输入固定结果；维度边界；原型距离/平分；分支目标、可达终点、有界循环                                |
| 可达性 | 提供每个计划原型/结局的见证答案或可证明搜索；未证明标为 unknown 并阻断发布，不能靠随机没抽到认定不可达 |
| 报告   | 三模式均有完整非 AI 报告；文案块选择无越界；AI 不能改结论；模板兼容                                    |
| 视觉   | 五基础状态完整，详细报告绑定明确；所需组件存在，props Schema 合法，素材可寻址                          |
| 授权   | 所有商业素材与字体来源证据完整，自动检查存在性 + 人工核实真实性                                        |
| 发布   | 验证证据绑定内容哈希与版本，人工批准；编辑后必须重新验证                                               |

结果分布可用固定种子的模拟回答观察区分度，但目标来自商品设计，不能强行要求每个原型概率相等。可达性与比例是两件事；高维模型证明困难时要求明确见证，不假称完整数学证明。

## 不可信导入与资源防护

拟议默认上限：压缩包 50 MiB、实际解压累计 150 MiB、单文件 20 MiB、文件数 500、压缩比 50:1；角色库扩展时可经审核调整，不无限放开。限制读取流和实际写入字节，而不只信任 ZIP 元数据。复杂度、图片像素数、JSON 深度和校验时间也需独立上限及超时。

只接受 manifest 列出的白名单文件。路径统一分隔符及 Unicode 规则后检查，拒绝绝对路径、盘符、`..`、空/重复/大小写冲突路径、符号/硬链接、加密条目、嵌套压缩包和 ZIP 外写入。隔离 staging、限制权限，不直接解到 public。失败清理 staged 文件，不留下半导入发布。

按真实魔数/媒体解析器校验，不只扩展名。拒绝脚本、HTML、可执行文件、宏、动态远程引用。SVG 默认拒绝不可信上传；需要时仅接收经平台审核的静态 SVG 并安全净化/栅格化，不能带 script、事件、foreignObject 或外链。图片限制尺寸/像素和解码资源；字体/音频同样需白名单及审核。资产交付设置正确类型，内容不在受信主域执行。

哈希验证完整性，不验证作者身份或授权真假；恶意文件扫描可作为纵深能力，不能替代白名单、限额和隔离。作者审核与自动结构验证分开记录。未授权资源不能通过占位“approved”绕过。

## 专属组件注册

Codex 在主项目开发组件，经代码审查、测试与视觉审核后随应用发布。注册表固定 `registryId`、组件版本、props Schema、页面状态/引擎能力及最低运行时版本。包只引用 ID 与版本，不提供源代码、import 路径或 URL。

保留支持旧 ProductVersion 的组件版本；移除前清点报告/会话引用并制定兼容迁移。富视觉配置只能选可信配方/允许参数，禁止危险 HTML、CSS 注入、任意网络地址和执行字符串。业务得分/凭证处理不交给布局组件。

## 版本、升级与回滚

包版本与商品发布版本不可变；重复导入同 packId/version/hash 幂等返回同草稿/记录；同 ID/版本不同 hash 拒绝。重新编辑或修改资源产生新版本/新证据。发布 ProductVersion 绑定逻辑、视觉、报告、资源和注册组件。

升级只影响新激活；活跃会话和已完成报告保持旧引用。回滚将商品“当前发布”指针切到批准的旧 ProductVersion，不重写历史。数据库迁移和应用组件回滚必须仍可读取旧报告 Schema。共享素材使用不可变内容寻址，不允许替换同路径图片改变历史。

## D0 提案限制

上述阈值、字段和状态需后续用真实代表包验证。没有 ZIP 安全验证实现、最终 JSON Schema、评分引擎或注册表。需要恶意包夹具、兼容矩阵与 PostgreSQL 事务测试后才能宣称导入安全或一次完成得到保证。
