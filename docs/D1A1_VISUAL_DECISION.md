## 人物揭晓机制

当前预览的未揭晓封面组件没有report/identity参数，只读取无人物山水。结果组件只接收只读 `HistoricalReportView`，由研究路由明确注入合成fixture。封面SSR HTML没有李白、人物立绘URL或称号，浏览器也不请求该立绘；不是用CSS隐藏已下载人物。

正式流程的后续合同：

1. cover/question/resume只接收介绍、题目、进度等各自DTO，不能混入结果姓名、画像、称号或候选排名。
2. 只有可信服务完成确定性评分并锁定报告后，授权结果路由才提供人物身份和已审核资产引用。前端点击、动画结束或本地状态不能授予完成权威。
3. reveal与report接受固定结果快照；视觉层不推断人物、重算分数或调用模型。未知资源ID阻断正式渲染，不替换为默认人物。
4. poster使用独立脱敏分享DTO，无访问Key、回答原文或身份凭证。实际分享授权/导出尚未实现。

本轮没有上述服务或权限验证；公开研究result仅展示固定合成内容，可以直接访问。类型不是运行时Schema，也不授予正式揭晓权限。

## 七类结果展示槽位

`features/report/historical-view.ts`为展示DTO提案，`historical-fixture.ts`是独立合成数据；主题只读其显式接口。

| 槽位               | 展示内容                            | 权威/缺资料约束                                                          |
| ------------------ | ----------------------------------- | ------------------------------------------------------------------------ |
| 匹配人物与称号     | 姓名、称号、时代、肖像ID、短句      | 正式值来自锁定报告；当前李白仅概念示例                                   |
| 核心性格维度       | 维度ID/名称、倾向标签、文字说明     | 当前突出/均衡/内敛均为合成标签，没有分数或百分比；真实口径待引擎与Schema |
| 匹配依据           | 摘要、倾向证据与意象对应            | 当前不引用真实回答；未来来源可追溯，不编造答题经历                       |
| 主要优势与潜在短板 | 分开呈现优势和需留意的倾向          | 不做诊断，不把倾向当能力/命运结论                                        |
| 其他相似人物       | 人名、比较理由                      | 当前苏轼/陶渊明为合成关系，无排名/概率；没有资料明确留空                 |
| 文化人物介绍       | 时代/经历/文化介绍及来源审核状态    | 与性格解释分开；当前来源审读pending，无史实通过声明                      |
| 收藏海报信息       | 姓名/称号、短句、品牌署名、娱乐说明 | 只展示字段，不提供虚假下载/保存按钮                                      |

七类槽位不是七个评分模块。本轮不实现报告模式选择、生产快照持久化、发布或资源Schema验证器。正式ReportMode仍按REPORT_MODES中的确定性结论规则推进。

## 统一人物与中性素材规范

未揭晓阶段优先使用无人物情境；本轮直接复用已生成的山水概念图，没有委托新人物。若以后增加中性角色，不得复用某结果的可辨识脸、服饰标志、姓名、称号或剪影；要独立素材ID和审批。本轮不使用人物剪影/Emoji替代立绘。

所有结果角色采用同一细笔设色/轻水墨风格、左上柔光、青绿/米白/小面积旧金；按人物自身时代、年龄和身份制作，不能只换脸或衣色。透明母版建议≥1200×1800、头/手/衣袖留8%安全区、网页800×1200 WebP≤500KB，脸部焦点约x48%/y13%。支持浅纸和深青两底面，检查透明边缘、裁切及面部/手部；人物名、称号与肖像ID必须成对审核。

当前仅有李白概念立绘。`findConceptPortrait`只接受固定已入工程的概念ID，未知ID显示“该人物立绘待补齐”，不回退李白、不加载动态URL；正式未知资源阻断策略仍待Schema/发布阶段。完整原型名单、其他角色图和史实/服饰审读未完成。
