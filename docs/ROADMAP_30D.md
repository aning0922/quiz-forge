# 研发路线图（规划，非承诺）

## 当前事实与本轮范围

截至 2026-10-11（Asia/Shanghai），`main` 已合并 Visual V2-C 和 D1-C 的研究/合成演示证据；D1-D 的独立分支仍暂停且未合并。已合并的视觉演示、合成题目、合成本地恢复和 PNG 导出，不是正式评分、数据库、Key、导入器或已发布商品。

本轮只授权两项工作：更新全前后台、数据、资源和路线规划；以及 F1「首批测评资源版本底座」。F1 仅包含 `foundation.v1` 的有限运行时契约、测评工作区归属与资源引用、草稿纯逻辑、三结果 synthetic 参考包和结构验证 CLI。它不实现或宣称数据库、ZIP 解包安全、评分引擎、后台认证、审核发布、AccessKey 或消费者正式流程。后续每一阶段均须另获明确授权。

## 交付总原则

- 一个测评就是一个工作区；不要再引入与 `Product` 重复的 `Project` 实体。工作区拥有草稿、版本、资源清单、预览、审核与发布历史。
- 已发布版本不可编辑，固定逻辑、视觉、报告、素材和组件引用。编辑、导入或复制都只能产生新草稿版本。
- 自动结构通过、素材来源声明和审核状态均不能单独证明商业授权；`publishable` 必须保持 `false`，直到后续人工审核与发布门槛都满足。
- 研发端可使用受控工具和夹具；平台端永远重新验证不可信输入。包不携带源代码、任意 JS、HTML、动态 URL 或可执行规则。
- 每阶段的工程检查、截图或 CLI 成功只证明该阶段的技术门槛；视觉、内容、商业与人工审核独立记录。

## 与旧编号的映射

P0 为原 D0/D0.1/D1 的规划收口；F1 是 P1 前的最小参考底座，不等于原 D2 的完整 Schema。P1 汇集原 D2–D4 的完整 Schema、验证器和构建器；P2 将原 D5 与原 D15 中必须前置的认证、草稿、审核和工作区能力合并。原 D15 不再是后台首次出现，而在 P7 收口为运营功能完善、发布治理和审计扩展（基础安全从首个写接口开始）。

P3 对应原 D6–D8；P4 对应原 D9–D12；P5 对应首款接入、海报和内测闭环（原 D13–D16 的首款部分）；P6 对应原 D1-D/E 与其余运行器接入；P7 对应原 D16–D18；P8 对应原 D19–D30 中可选 AI、剧情、渠道和发布准备。该调序已获本次作者同意；只授权本轮文档和F1，不表示后续阶段已完成或自动获得实施授权。

## 首款参考包与资源时序

F1 的三结果 synthetic 参考包用于检验契约和工具接口：它不代表真实题库、历史结论、已批准人物资源或可销售商品。首款历史人物工作区先在 P3/P5 形成完整受控参考：题目、原型规则、结果资料、五状态配方、资源 manifest、正反验证例和每个结果的可达见证必须随版本固定。

七宗罪与动物主题保留在 P6。它们可并行进行不改变运行时契约的素材研究，但不能抢占首款的数据库、审核、引擎和 Key 闭环，也不能以研究页面或 pending 素材声明商品已可发布。

## 阶段阻断项

下列情况阻断进入相应后续阶段：F1 契约不稳定或混入发布语义；包工具接受可执行内容或缺少拒绝夹具；后台可绕过验证/审核直接发布；引擎无法提供固定结果或可达见证；完成事务无法保证一 Key 一报告；资源缺来源、授权证据或人工批准；海报泄露 Key/答案；未完成浏览器、实机、无障碍和人工验收；未确认经营或外部 H5 履约权限却接入交易或渠道。

每阶段完成后应独立提交、推送并记录实际验证、限制、人工验收项与下一阶段授权条件。路线图不构成自动执行、合并、部署或商业发布授权。
