## 原实例同机启停与恢复边界

官方已有入口是 `p2a:db start|status|stop --instance <id>`。必须由运行环境负责人在**原受管工作树根目录**使用，先核实原实例身份和当前状态。以下为相互独立的管理动作，不是顺序重放脚本；`QF_BETA_INSTANCE_ID` 应由负责人设为既有实例 ID，不在本说明固化当前体验服务配置。

负责人还需核对所拥有的应用、worker 和未决操作。停库前先停止应用并取得实际退出证明；未知写入或关闭状态继续保留，不能以 TTL、停止信号或空页面推断事务结果与清理资格。

| 动作       | 官方命令                                                                                          | 语义                                                            |
| ---------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 状态       | `TSX_TSCONFIG_PATH=./tsconfig.json pnpm --silent p2a:db status --instance "$QF_BETA_INSTANCE_ID"` | stopped 时只核本地身份，不证明数据库 schema 或业务内容          |
| 启动原实例 | `TSX_TSCONFIG_PATH=./tsconfig.json pnpm --silent p2a:db start --instance "$QF_BETA_INSTANCE_ID"`  | 核原 manifest／PGDATA、端口、启动归属及 DB 身份；不自动 migrate |
| 停止原实例 | `TSX_TSCONFIG_PATH=./tsconfig.json pnpm --silent p2a:db stop --instance "$QF_BETA_INSTANCE_ID"`   | 核身份后执行受管 PostgreSQL 停止；不删除业务图或素材            |

该实现绑定本机 PostgreSQL 18.4 和 `/opt/homebrew/bin`，不是任意主机的恢复工具。manifest 严格绑定原 `cwd` 和绝对路径；目录／配置还要求同 UID、0700／0600 权限及无符号链接，PGDATA、socket、端口、marker 和角色均有身份约束。搬目录、新 clone 或新 worktree 不能直接声称恢复原实例；`p2a:db init` 创建随机新库，不恢复旧业务图。显式 `migrate` 是写操作，不是只读验收或恢复命令。

Next 应用另需匹配的生产构建、私有资源和已核实的媒体运行环境。唯一私有配置入口是 `QUIZFORGE_P2A_CONFIG` 指向原工作树内的绝对 `runtime.json` 路径；应用不回退到 `DATABASE_URL`。监听地址／端口须与配置的 origin 一致，3100 是本次验收使用的独占端口。负责人确认这些条件后，才可在原根目录使用项目的 `pnpm start --port 3100` 启动应用；该命令不替代数据库启停、迁移、媒体准备或身份核验。本轮归档文档不核实或改变当前体验服务的运行状态。

目前没有已交付的 backup／restore／pg_dump／pg_restore 管理入口，也没有数据库＋私有资源的一致备份、跨路径／跨机恢复、恢复演练、自动快照保留或 PITR 的验收证据。**代码回溯／原实例同机重启可用；数据库＋私有资源一致备份及恢复演练仍是正式上线前待办。** 数据保护的后续决策见 [数据模型](../DATA_MODEL.md)。
