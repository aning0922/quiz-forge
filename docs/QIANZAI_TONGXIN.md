## Windows 本地 Art Factory 衔接

现有 Windows 生图流程仅有历史只读证据；独立CLI、W1、批量恢复和导出未据此宣称完成。B负责独立工具，A负责业务核心，主控收口输入、资源选择和接线，Astra独审高风险边界；最多两条实现流。

1. 工具先实现inspect/prepare/dry-run/run/status/resume与定向离线验证。保持现有SSH、ComfyUI、模型和全局配置，读取当前节点/队列后使用已核实工作流；832×1216只适用于W1基线，不强迫所有正式素材同尺寸。
2. W1限定一个虚构角色、一个明确seed、一次POST和一张图；实际提交待主控核定技术输入与可用队列，不采用正式人物或重画封面。客户端故障注入检验丢回执恢复，不真断SSH/重启服务。
3. 人物样张依实际缺口和槽位确定。建议李清照主图最多2候选；选中风格与裁切经作者确认后，若其余四人全部确需新增，首批累计最多8候选，包含这2张。找回可复用原件则减少；其他局部修复不自动纳入扩大批次。
4. 单项batch=1、设备自动并发=1；本地锁不能阻止其他客户端。dry-run明确展开角色/用途/候选/seed/工作流/模型/参数/输出，random先固化。
5. 请求与原身份先持久化，再单次POST。超时/断线/5xx/丢失或不可解析回执保持UNKNOWN并暂停后续自动提交；只查询原任务，空history不证明未执行，客户端prompt_id不当幂等键。
6. resume按逐项状态处理：未发项才首次提交，已接受继续查询，UNKNOWN仅对账，成功项只补下载/整理。GET下载至.part，完整解码/尺寸/hash核对后原子提交；清单失败不重做GPU任务。
7. 总览保留每个计划项的成功、失败、下载未完成和UNKNOWN；候选默认pending。选定资源再生成必要派生/固定清单，不自动批准、上传全部运行缓存或替换正式引用。
