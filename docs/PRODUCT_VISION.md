# 产品愿景

## 定位

QuizForge 是趣味测评商品研发、导入、运行与运营平台。核心模式是 **Codex 精品测评研发 + QuizPack 标准化验证/导入 + QuizForge 统一运行与运营**：每份测评先成为独立工作区，在其中完成题目、确定性规则、结果资料、专属视觉、资源和预览，再经验证与人工审核发布为不可变版本。后台 AI 是可选辅助，不能替代研发、审核或确定性运行。

测评是产品组织的中心：一个 `Product` 就是一份测评工作区，不额外建立语义重复的 `Project`。工作区按版本管理草稿、资源、预览、审核、发布、Key 和运营记录；类别只用于公共目录发现和运营筛选，不能决定资源归属或把不同测评强行共用视觉。

商品价值闭环是：有世界观的封面 → 易读、沉浸的答题 → 值得收藏的结果 → 可保存的分享海报。程序保持评分可复现；作者审核题意、结论、视觉和商业适用性。

## 三个产品面

### 公共目录

公共目录按类别、主题或商品属性展示已发布测评的安全摘要、批准封面、娱乐说明和明确授权的演示入口。它不暴露草稿题目、评分配置、资源源文件、版本历史、Key 或审核信息。类别不是 ThemeDefinition，也不是工作区资源目录。

### 消费者体验

正式答题以对应商品的有效 AccessKey 进入固定版本会话。消费者可暂存恢复，但每个 Key 只能正式完成一次；完成后原链接只读打开锁定报告，不能因清理浏览器或新版本发布而重新评分。分享使用独立、可撤销的只读授权，海报、分享地址和公开数据均不得携带原始 Key 或原始答案。

当前已合并的历史人物页面、合成答题、本地恢复和 PNG 导出是视觉/交互研究证据，不是上述正式消费者服务。

### 测评工作区后台

后台按工作区组织，不以全局主题页代替项目管理。建议信息架构是：概览、内容与规则、结果资料、视觉与资源、版本、预览、验证、审核、发布、Key、聚合统计与审计。作者、审核/发布者和 Key 运营者拥有不同权限；消费者 Key 不能取得后台权限。

创建空草稿、导入、复制已批准版本和编辑都产生新草稿。草稿经过结构/规则/资源验证和完整预览后才能提交审核；已发布版本不允许原地修改。审核批准创建固定发布版本，随后才可发放 Key。已发布内容的改动必须从新草稿重新开始。

## 版本、资源与报告策略

工作区版本固定逻辑、视觉、报告模板、素材 manifest 和受控组件版本。资源默认归属于一个工作区版本；跨测评复用必须通过已批准、不可变且带内容哈希的共享资源包显式引用。来源或 `licenseClaim` 是声明，不等于真实可商用授权；自动验证通过也不等于可发布，人工审核仍是必要门槛。

报告可采用 DETERMINISTIC、COMPOSED 或可选 AI_ENHANCED。三种模式的结论均由确定性引擎产生。AI 只能在结论与完整基线已锁定后增强指定文案，不能更改分数、原型或结局；失败时封存完整基线，历史读取不再次调用模型。

精品布局由主项目中经过审核、测试和发布的 React 组件提供；包只能引用固定 ID、版本和 props Schema，不能带入源代码、任意 JS、动态 URL 或任意 HTML。

## 首批测评与时序

| 测评工作区     | 预期确定性引擎 | 独立视觉身份                          | 推进时序                                        |
| -------------- | -------------- | ------------------------------------- | ----------------------------------------------- |
| 历史人物匹配   | 原型匹配       | 新中式人物志、藏馆/卷轴、原创古人角色 | 首款参考与精品内测；现有页面仍是 synthetic 研究 |
| 七宗罪趣味人格 | 多维度评分     | 暗黑幻想、纹章、属性面板              | 首款正式闭环后补足五状态                        |
| 动物人格匹配   | 原型匹配       | 原创 Q 版动物、贴纸和收藏卡           | 首款正式闭环后补足五状态                        |

F1 先提供一个三结果 synthetic 参考包，只用于验证有限契约、资源归属和工具接口。它不是正式题库、评分规则、历史事实、素材授权或可销售商品。首款历史人物测评在后续引擎、审核、Key 和报告事务完成后，才成为正式内测候选。七宗罪和动物主题可继续进行不改变契约的视觉研究，但不能绕开首款闭环，也不能用 pending 素材宣称可发布。

七宗罪仅为娱乐性格测评，不作为心理诊断；历史人物是性格原型，不声称精确还原或科学匹配。角色与插画必须原创或有明确、经审核的商用授权，不能使用未经许可的现成 IP。

## 开发与发布路线

优先顺序是：P0 规划统一 → F1 有限参考底座 → 包工具与不可信输入验证 → 数据与最小后台工作区/审核 → 双确定性引擎与注册预览 → Key、会话、完成事务与锁定报告 → 首款精品内测 → 其余两主题的十五状态 → 运营完善与可选 AI/剧情/渠道能力。完整定义、阶段依赖和退出条件见 `ROADMAP_30D.md`；QuizPack 的 F1 与后续边界见 `QUIZPACK_SPEC.md`。

此顺序把“最小受控后台工作区”前移到数据库和包验证之后，避免已有草稿与版本数据却没有审核边界；但不把完整运营、批量 Key、统计或交易后台提前到首款正式闭环之前。

## 商业与发布前置条件

小红书经营类目和外部 H5 履约权限尚未确认。不得假设已获商品经营、支付、订单 API 或自动发货权限，不开发平台强耦合交易流程，不自动发布商品，不承诺收入。第三方接入前须确认平台协议、合法销售品类、数据处理边界与履约渠道。

正式发布还必须满足：已注册并测试的确定性规则、包安全验证、数据库事务与访问控制、版本/资源/报告不可变快照、素材和字体的授权证据与人工批准、真实海报脱敏导出、浏览器/实机/无障碍/性能证据，以及作者对内容与视觉的人工验收。当前任何研究页、自动化检查或 F1 验证都不能替代这些条件。
