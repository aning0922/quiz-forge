# 三种报告模式（D0 设计）

最终结论统一由确定性评分引擎产生。无论报告模式，正式提交同事务保存规范化答案、维度分数、原型/结局、逻辑版本、商品版本、视觉/素材/组件版本、报告模板版本与完整非 AI 基线快照。每 AccessKey 只正式提交一次，暂存/恢复不消耗，完成后不可重新答题或改变结论。

## 模式与运行

| 模式          | 输入与处理                                                       | AI 依赖              | 封存时机                                    |
| ------------- | ---------------------------------------------------------------- | -------------------- | ------------------------------------------- |
| DETERMINISTIC | 确定分数/原型/结局 + 固定模板生成报告                            | 无                   | 提交事务保存最终快照                        |
| COMPOSED      | 确定原型、维度分数、白名单关键答案 → 预设模块条件 → 固定顺序组合 | 无                   | 提交事务保存最终快照                        |
| AI_ENHANCED   | 先生成完整基线与锁定结论，再增强指定文案块                       | 可选；失败不破坏基线 | 增强成功或失败/超时回退后仅一次封存最终快照 |

COMPOSED 的模块选择也是声明式、确定性规则：有限条件 DSL、互斥/覆盖检查、可复现顺序、缺模块回退；不能以字符串 eval 或随机文案替代。模板、文案块和选择规则都随版本固定。

AI_ENHANCED 关闭、无权限、限额耗尽或不可用时直接封存完整基线，测评结论及用户查看不受影响。不得把简短错误提示当完整失败报告。

## AI 内容合同

只提供已确定的原型/分数解释与经过验证的最少回答摘要，不发送 Key、身份、联系信息、未必要原始自由文本或敏感个人经历。摘要字段白名单，不把用户内容作为指令。

输出拟议 `report-prose.v1`：已声明 sectionId 与纯文字；Schema 拒绝额外分数/原型/结局字段，限制数量/长度，禁用任意 HTML、URL 或执行内容。分数和结果名称由平台渲染，AI 无更新通道。

不得改结论、编造用户未提供经历、输出医学诊断、科学心理评估或命运预测断言。Schema 不能保证文意正确；需要输出策略验证、受控提示词、测试与审核机制，违规或无法确认时使用完整基线，不声称程序已证明语义安全。

## 唯一任务与最终快照

提交事务写报告、消耗 Key、写唯一增强任务/事务 outbox（若模式启用）。建议 `AIReportJob(report_id)` 唯一，任务状态 queued/running/succeeded/failed/fallback-sealed；worker 通过数据库租约/比较更新领取，持久化请求 ID、幂等键、尝试记录及超时。

完整基线和结论从提交时不可变。AI 模式的最终文案快照只允许从 pending 进入一次 sealed 状态，成功结果或回退基线二选一；封存后迟到的响应不能改写。页面等待时可展示完整基线和“文案整理中”，结论不变化；一旦成功/失败封存，此后只读最终快照。报告查看绝不创建新任务或再次调用 AI。

同一有效测评最多接受一次成功增强，数据库唯一任务 + 最终快照 compare-and-set 防止多个 worker 接受结果。重试复用同任务/供应商幂等键；已成功不得重试。供应商请求超时可能已经成功，需通过幂等 API 或查询状态确认。供应商不提供这种能力时，遇未知成功回退并封存，禁止盲重试；不能只靠本地锁宣称外部调用 exactly-once。

用户请求超时不回滚已经提交的测评；用原链接读取同报告。增强失败不释放 Key。增强成功报告、回退原因及供应商版本记录用于审计，但不保存多余敏感输入。未来若要重新增强，需新的明确产品政策，不能悄悄更改历史结果。

## 测试计划（未实现）

固定答案固定结论；COMPOSED 分段选择边界与覆盖；一次提交/并发重试只有一报告；AI 不可用/Schema 无效/违规输出/限额/超时均产生完整基线；多个 worker 与迟到响应只封存一次；已完成/新商品版本/回滚/反复访问不重新评分或调用 AI；旧报告 Schema 与旧组件可兼容读取。

D0 只建立模式类型和设计文档，没有生成服务、任务队列、数据库锁或上述业务测试。后续采用单体数据库任务表与 worker 优先，不因可选增强引入微服务。
