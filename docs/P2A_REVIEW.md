## 七项发现及闭合证据

以下旧行为均指修复前代码，不应理解为最终实现仍有对应问题。

### P2A-R1：P2，私有配置 FIFO 可阻塞读取 — 已关闭

旧 runtime 先以 O_RDONLY/O_NOFOLLOW 打开，再用 fstat 拒绝非普通文件；无写端的 FIFO 会阻塞在打开阶段。独立探针在本聊天创建的私有临时目录构造 FIFO，子进程超过一秒仍未返回，随后只终止该探针，没有访问数据库。

`466a9cd` 加入 O_NONBLOCK，再检查普通文件、权限、属主和大小，并按实际最多 16384 bytes 读取。FIFO 拒绝回归独立通过；非普通文件不能在到达类型检查前无限等待。

### P2A-R2：P2，runtime 与 HTTP 对 origin 端口接受范围不一致 — 已关闭

旧 runtime 接受显式 `:80`，HTTP 使用 URL 标准化后却拒绝同一配置。总控冻结 canonical `1024..65535` 契约后，DB 与 Auth 分别在 `466a9cd`、`8aba454` 对齐。独立单测确认拒绝默认端口、1023、65536、前导零及别名，接受 1024/65535 两端点。

### P2A-R3：P2，连接选项继承环境 PGSSL/PGDEBUG — 已关闭

旧 openSql 未显式指定全部相关 postgres.js 选项；独立构造不发查询的延迟客户端，确认环境变量可改变 ssl/debug。`466a9cd` 显式固定 postgres.js 3.4.9 的连接选项，隔离通用 PG 环境输入。污染环境回归独立通过；未通过探针连接任意数据库，也未输出连接秘密。

### P2A-R4：P2，CI 在不可用上下文读取 service 动态端口 — 已关闭

旧 workflow 在 job env 使用 `job.services.postgres.ports[5432]`，该位置没有 job 上下文。依据 [GitHub Actions 上下文可用性表](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability)核对后，`b886d69` 改为受控脚本启动本次容器，再读取实际 loopback 动态端口并在同一进程链执行 bootstrap/test:db。修复已做静态复核；不以脚本存在代替实际远端 CI 成功。

### P2A-R5：P2，CI 密码可预测且可能进入容器创建日志 — 已关闭

旧配置使用可预测的运行标识构造密码，并通过 service env 进入 runner 容器创建参数。`b886d69` 改为每次随机 32 bytes 密码，先注册掩码，再写入私有临时密码文件，通过 POSTGRES_PASSWORD_FILE 挂载给固定 digest 的官方镜像。Docker argv 不含密码原文，不把密码写入 GITHUB_ENV；bootstrap 后清除进程环境变量。

独立核对脚本及官方镜像 entrypoint 的文件读取顺序，0600 密码文件与该入口兼容。未在本聊天启动 Docker；实际容器执行和远端日志结果仍须由总控 CI 提供。

### P2A-R6：P2，CI 未验证清理对象时可静默成功退出 — 已关闭

旧 cleanup 在 inspect 失败、容器 ID 不合规或本次标签不匹配时跳过删除，却可能保留退出码 0。`df9e45d` 明确返回固定清理错误和非零退出；仅验证为本次容器后才删除，删除失败同样非零。

独立运行五项 stub 回归及 bash 语法检查通过，覆盖清理成功、身份无法确认与删除失败。没有借此删除或检查本机真实容器。

### P2A-R7：P2，pg_ctl 启动返回失败后的实际进程未获补偿 — 已关闭

旧 init 只有 pg_ctl 成功返回才设置 started；独立全 stub 探针令启动返回非零，确认 start 已尝试但 stop 未尝试，错误仅称实例保留。[PostgreSQL 18 pg_ctl 文档](https://www.postgresql.org/docs/18/app-pg-ctl.html)明确指出等待超时不代表后台操作不会继续成功。

`720b982` 将 init/start 收口到共同实现：核验私有 PGDATA，拒绝既有 postmaster，取得排他 start.lock；每次启动附带随机 cluster_name 标记。失败后同时核对 PGDATA、端口、socket、监听地址、PID、启动时间与本次 postmaster.opts 标记，确认后才调用 pg_ctl stop，并核验 PID 文件消失。已记录启动成功后的初始化/身份检查失败也使用同一补偿边界。

未 spawn 且无 PID 的已知失败可返回 NOT_STARTED；已 spawn 但事实缺失、旧/外来/被替换进程、标记不符或停止失败均保留明确 CLEANUP_REQUIRED，不把瞬时无 PID 当作没有延迟启动。既有 guard 不覆盖，释放只删除本次 inode。不能确认身份时不盲停进程、不盲删实例。

最终 13 项受控启动故障测试独立通过，使用合成私有文件与注入命令，不启动真实 PostgreSQL。实现流另在 [数据库实施记录](P2A_DATABASE_IMPLEMENTATION.md)报告了真实启动后注入失败的 init/start 补偿及健康 start/stop；这是实现流证据，本聊天没有重复执行。

## 其他复核结论

- Auth 写入与管理停用统一先取得 `pg_advisory_xact_lock(72461,1)`，锁后重查当前身份、会话及时间；touch 条件包括未撤销、idle/absolute 未到期及 operator active，不能复活已失效会话。时间依据实际 DB clock_timestamp，DTO 时间转换不授予有效性权威。
- preauth 与 session 是独立 token/行；登录只消费一次挑战，失败计数和审计提交后再返回业务失败。五次撤销、并发限额、跨挑战/跨会话 CSRF 和当前角色读取均有真实数据库验证。read-only 无冻结写能力，没有 publish/key 能力。
- 写 API 在数据库操作前检查精确 Origin 和对应 CSRF；Cookie 为 HttpOnly、SameSite=Strict、Path=/、无 Domain，Secure=false 仅用于明确的 local-http-p2a。错误响应固定 code/requestId，不返回原始异常。API 带 no-store；Studio RSC 强制动态渲染，不写 Cookie，不使用客户端身份代替数据库判断。
- HTTP 实际字节与五秒期限的同步工作/空块微任务边界由总控先行修复于 `f923488`，已独立复核并通过相关单测，不重复计为上述独立发现。
- PUBLIC 列授权疑点未成立：PG18 表级 REVOKE 会撤销相关列授权。最终提交修正旧注释并增加真实重放回归；本聊天没有把已排除疑点计为漏洞，也没有在最终 head 重跑新增数据库用例。
- E2E 原延迟拦截器与 unroute 竞争由 `530e2e5` 修复为页面生命周期内保留已释放的 handler；未吞掉异常。认证项目关闭 trace/video/自动失败截图，无 HAR，手工截图只允许空凭证输入或登录后的非敏感状态。没有把 CSRF、Cookie 或凭证原文加入本文。

## 限制与交接

P2-A 是本机、loopback、单运营空间认证基础，尚非远端多租户/生产身份系统。文件与 PGDATA 管理以受控本机工作树为前提；遇到无法确认的启动或清理结果明确要求检查，不保证自动恢复所有操作系统故障。凭证/配置仍只允许私有文件保存；合成测试身份同样不能泄漏秘密。

独立审查未发现剩余 P1/P2，可由总控继续已授权的最终检查和 Draft PR 收口。尚未完成的检查不能标为成功；没有因此授权 main 合并、生产迁移、部署或商品发布。后续 Product/导入、评分/报告及消费者流程应按各阶段单独交付与验收。
