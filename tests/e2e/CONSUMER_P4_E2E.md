# P4 consumer-flow production E2E

`consumer-flow.spec.ts` defines the eight exact case IDs in the frozen physical fixture contract. It uses the actual Studio UI to create a play and three browser-generated Keys, then real consumer exchange/save/complete/report/resource/PNG endpoints. UNKNOWN cases first relay the original browser request through bounded native HTTP to the actual server and validate its receipt, then intentionally hide that response. Reload must preserve the same original request and perform no automatic replacement write. Recovery is explicit and binding-bound.

The original private Key link is downloaded by the real browser to a test-owned 0700 directory and 0600 file in `.cache/p4-e2e-private/<runId>`; content is checked against the issued digest without logging it. Its raw fragment is injected through an isolated evaluate call, following the existing Studio credential input pattern. Raw Key never appears in `goto`, locator `fill`, APIRequest, CLI or assertion arguments. Fragment removal is checked before the actual exchange. Trace/video/automatic screenshots are disabled, and failure closes all answer-bearing contexts before exposing a finite case error to the reporter. The helper never contacts external origins or accepts exchange over its native transport. Safe screenshots and the final PNG are intentional synthetic UI artifacts; private links are not attached to the HTML report.

Native reads/writes carry Cookie and CSRF only in Node memory, avoiding Playwright APIRequest fetchLog. Every fault is rebuilt without cause, URL, request headers/body or remote text. Requests allow only fixed P4 fixture Studio paths and UUID-scoped consumer paths; resource queries must have the exact bounded selector. Cookie selection uses the actual target path. Streams are bounded by endpoint budget, encoded/redirected responses are rejected, and errors are capped at 4096 bytes. Cross-session authority probes reuse the valid source grant only inside this native helper.

The private fixture loader checks exact local instance directory, owner/mode, no symlink, bounded file and stable inode. CLI receives only `prepare|finish <runId>`. Observation files contain exact verified play/Key/state/report receipts and public bootstrap facts plus a privately computed grant digest; raw/CSRF/report body is absent. A grant is marked logged out only after observing the actual logout 204. Final Key facts are freshly read before finish. Only all eight actual first-run successful cases can generate suiteCompletion; filtering, skip, expected failure, retry, repeat, unknown or duplicate case blocks finish. Failures retain evidence for root-owned actual server exit and cleanup; B does not issue a cleanup/exit proof.
